# Code structure

This document lists the modules, classes and main functions in the system,
which node uses them, and who owns them. It complements
[ARCHITECTURE.md](../ARCHITECTURE.md), which defines *what* the system does;
this file defines *where* the code lives.

Signatures are a guideline for the implementation, not a contract. The owner of
a module may change them; a change that affects another owner's code is agreed
in the pull request. Only the ROS interfaces in `rescue_interfaces` are frozen.

**Conventions**

- Python 3.8 and NumPy 1.17: type aliases and other runtime expressions use
  `typing` (`Tuple`, `List`, `Dict`, `Optional`, `Callable`), not `list[int]`
  or `X | None`. No `match` statements.
- `core/` never imports `rclpy` or ROS message types. It works on plain Python
  types and NumPy arrays, so it can be unit-tested without ROS.
- `nodes/` converts between ROS messages and core types and handles timing and
  communication. Algorithms do not belong there.
- Positions are `(x, y)` tuples in metres in the `map` frame (`Point`). Grid
  cells are `(row, col)` tuples (`Cell`), where `row` follows y and `col`
  follows x. Both aliases are defined in `core/geometry.py`.
- `core/` never reads a clock. Functions that need time take `now: float`
  (seconds, simulation time).
- Dependencies are passed in through constructors (allocator, cost function,
  meeting function), so tests can pass fakes.
- Robot code uses only `numpy`, `opencv` and ROS 2 packages.

```
│   ├── traffic.py             Two robots on one map: peer filter, conflict, priority (A)
│   ├── lidar.py               Scan points, sectors, safety stop check                (B)
│   ├── controller.py          GoToPointController                                    (B)
│   ├── marker_registry.py     Sighting, Report, MarkerRegistry                       (A)
│   ├── viewpoints.py          Viewpoint generation                                   (A)
│   ├── allocation.py          GreedyAllocator                                        (A)
│   ├── meeting.py             Meeting points                                         (C)
│   └── mission.py             Mission state machine: events in, commands out         (C)
└── nodes/
    ├── robot_handler.py       RobotHandler   (runs in every robot namespace)  (B)
    ├── marker_detector.py     MarkerDetector (runs once, global)              (B)
    └── leader.py              Leader         (runs once, global)              (C)
```

**One class, many instances.** Each node class is written once. The launch file
starts `RobotHandler` once in each robot namespace (`/tb3_0`, `/tb3_1`) and
`MarkerDetector` and `Leader` once without a namespace. The code never contains
a robot name: `RobotHandler` uses relative topic names (`scan`, `odom`,
`cmd_vel`, `navigate_to`) and reads its robot name from `self.get_namespace()`;
all nodes read the list of all robots from the `robots` parameter.

| Module | Used by node |
|---|---|
| `geometry` | all |
| `grid`, `distance_transform` | `robot_handler`, `leader` |
| `path`, `traffic`, `lidar`, `controller` | `robot_handler` |
| `marker_registry`, `viewpoints`, `allocation`, `meeting`, `mission` | `leader` |

**Dependency direction.** `nodes/` imports `core/`; never the other way.
Inside `core/`, `mission.py` depends only on `geometry.py` and receives the
allocator, the cost function and the meeting function as constructor arguments.

### `core/grid.py` (A)

**`class GridMap`** — an occupancy grid with metric coordinates.

| Member | Signature | Purpose |
|---|---|---|
| attributes | `occupied: np.ndarray` (bool, shape `(rows, cols)`), `resolution: float`, `origin: Point` | Grid data and placement; row 0 lies at the origin's y |
| `from_occupancy_grid` | `@classmethod (data: Sequence[int], width: int, height: int, resolution: float, origin: Point, occupied_threshold: int = 65, unknown_is_occupied: bool = True) -> GridMap` | Build from the fields of a `nav_msgs/OccupancyGrid` |
| `from_yaml` | `@classmethod (yaml_path: str) -> GridMap` | Load a map file (`.yaml` + `.png`), used in tests. Flips the image rows (PNG row 0 is the top of the map) and imports Pillow inside the function |
| `world_to_cell` | `(x: float, y: float) -> Cell` | Metres to `(row, col)` |
| `cell_to_world` | `(row: int, col: int) -> Point` | `(row, col)` to the cell centre in metres |
| `in_bounds` | `(row: int, col: int) -> bool` | Cell inside the grid |
| `downsample` | `(factor: int) -> GridMap` | Coarser grid; a cell is occupied if any sub-cell is |
| `inflate` | `(radius: float) -> GridMap` | Grow occupied cells by `radius` metres (circular, NumPy) |
| `is_known_wall` | `(point: Point) -> bool` | Point in an occupied cell or outside the grid. Used on the static grid grown by one cell, to drop lidar points on known walls |

`robot_handler` and `leader` build the static grid with
`from_occupancy_grid(...).downsample(factor)`, where `factor` is
`grid_resolution` divided by the map resolution (10), and the planning grid with
`inflate(inflation_radius)`. `robot_handler` also builds the known-wall grid with
`inflate(grid_resolution)`.

### `core/distance_transform.py` (A)

Distance transform as in Corke, *Robotics, Vision and Control*, chapter 5
([ARCHITECTURE.md §6.2](../ARCHITECTURE.md#62-path-planning-distance-transform)).

| Name | Signature | Purpose |
|---|---|---|
| `cost_field` | `(blocked: np.ndarray, resolution: float, sources: Iterable[Cell]) -> np.ndarray` | Travel distance in metres from the nearest source to every cell; `inf` for blocked and unreachable cells. Repeated relaxation over the 8-neighbourhood with steps `h` and `√2·h`; a diagonal step only if both orthogonal neighbours are free |
| `wall_distance` | `(occupied: np.ndarray, resolution: float) -> np.ndarray` | Distance from every cell to the nearest occupied cell: the same relaxation with all occupied cells as sources and no blocked cells |
| `descend` | `(field: np.ndarray, start: Cell) -> Optional[List[Cell]]` | Steepest descent from `start` to a source, with the same corner rule (a diagonal step only if both orthogonal neighbours have a finite cost); `None` if `start` is unreachable |
| `nearest_free_cell` | `(blocked: np.ndarray, cell: Cell, max_radius: int) -> Optional[Cell]` | Move a start or goal out of an inflated obstacle |
| `cost_at` | `(field: np.ndarray, grid: GridMap, point: Point) -> Optional[float]` | Field value at a metric point; `None` if unreachable |

**`class DistanceTransformPlanner`**

| Member | Signature | Purpose |
|---|---|---|
| `__init__` | `(avoid_radius: float, max_snap_radius: int)` | Radius of the discs around `avoid` points (`peer_plan_clearance`); search radius for snapping in cells (0.5 m, so 5 cells) |
| `plan` | `(grid: GridMap, start: Point, goal: Point, avoid: Sequence[Point] = ()) -> Optional[List[Point]]` | Snap start and goal to free cells of `grid` (without the discs), block discs around the `avoid` points for this call only, compute the field from the goal, descend from the start, convert with `cells_to_points` and simplify with `simplify_path` on the same blocked cells. `None` if there is no path |

| Member | Signature | Purpose |
|---|---|---|

### `nodes/robot_handler.py` (B) — one class, one instance per robot namespace

**`class RobotHandler(rclpy.node.Node)`**

| Member | Signature | Purpose |
|---|---|---|
| `__init__` | `()` | Parameters (logged at start), robot name from `get_namespace()`, the other robot from `robots`; subscriptions `odom`, `scan`, `/map` (`TRANSIENT_LOCAL`) and `/<peer>/odom`; publisher `cmd_vel`; a timer that creates the action server once the map and the pose are known; `self.planner = DistanceTransformPlanner(...)`, `self.controller = GoToPointController(...)` |
| `on_map` | `(msg: OccupancyGrid) -> None` | Static grid, planning grid and known-wall grid |
| `on_odom` | `(msg: Odometry) -> None` | Store the latest pose |
| `on_peer_odom` | `(msg: Odometry) -> None` | Store the other robot's position and its velocity in the map frame (twist rotated by its yaw) |
| `on_scan` | `(msg: LaserScan) -> None` | Map-frame points (`scan_to_points` with the latest pose) without known walls and without points near the other robot (`remove_near`), stored for the safety stop; the raw ranges are stored for the rear check |
| `on_ready_timer` | `() -> None` | Create the action server, in a `ReentrantCallbackGroup`, once the map and the pose are known |
| `goal_callback` | `(goal_request) -> GoalResponse` | `ACCEPT` |
| `cancel_callback` | `(goal_handle) -> CancelResponse` | `ACCEPT` |
| `handle_accepted_callback` | `(goal_handle) -> None` | `self.active_goal = goal_handle`, then `goal_handle.execute()` |
| `execute_callback` | `(goal_handle) -> NavigateTo.Result` | `navigate`, then `spin` if requested. `reached` → `succeed()`, cancel requested → `canceled()`, otherwise `abort()`. try/finally publishes zero velocity through `publish_velocity`, so only while the goal is the active one |
| `navigate` | `(goal_handle, target: Point) -> str` | Plan, follow, recover and replan. The replan count and the conflict timer are local and survive conflict replans. Returns `reached`, `no path`, `stuck`, `peer`, `preempted` or `cancelled` |
| `plan_path` | `(goal_handle, target: Point) -> Optional[List[Point]]` | Stop with `publish_velocity(goal_handle, 0, 0)`, then plan with the other robot's disc, unless the goal lies inside the disc; plan without the disc if that gives no path |
| `follow_path` | `(goal_handle, path: List[Point], state) -> str` | Control loop every 0.05 s: active-goal and cancel checks, waypoint switching, safety stop, conflict check and right of way, progress monitor, feedback. `state` carries the conflict timer from `navigate`. Returns `reached`, `stuck`, `replan`, `peer`, `preempted` or `cancelled` |
| `recover` | `(goal_handle) -> str` | Reverse up to `reverse_distance` while the rear sector is clear and the other robot is not behind; returns `done`, `preempted` or `cancelled` |
| `spin` | `(goal_handle) -> str` | Rotate `spin_angle` at `spin_speed`, ends after twice the nominal time at the latest; returns `reached`, `preempted` or `cancelled` |
| `obstacle_ahead` | `() -> bool` | `points_ahead` on the latest filtered scan points |
| `peer_blocks` | `(path: List[Point], index: int) -> bool` | `peer_conflict` with the other robot's latest position and velocity |
| `publish_velocity` | `(goal_handle, v: float, omega: float) -> bool` | Clamp and publish only if `goal_handle` is the active goal; returns `False` otherwise. Every velocity command, including every stop, goes through it, so a replaced goal can never stop the goal that replaced it |

`main()`: create the node and spin it in a `MultiThreadedExecutor(num_threads=4)`.

### `nodes/marker_detector.py` (B) — one class, one global instance

**`class MarkerDetector(rclpy.node.Node)`**

| Member | Signature | Purpose |
|---|---|---|
| `__init__` | `()` | Parameters `robots` and `marker_max_range` (logged at start); TF buffer and listener; one subscription to `/<robot>/aruco_markers` per robot; publisher `/found_marker` (queue depth 50); steady-clock timer for the failure log |
| `on_markers` | `(robot: str, msg: ArucoMarkers) -> None` | Queue the message and try it at once: for every marker with ID 0–4, transform, range filter, publish. Stays queued if the transform is not available yet |
| `to_map_frame` | `(robot: str, position: Tuple[float, float, float], stamp: Time) -> Optional[Tuple[float, float, float]]` | Look up `map ← <robot>/camera_rgb_optical_frame` at the image time without waiting and apply it with `transform_point`; `None` if the transform is not available (yet) |
| `on_retry_timer` | `() -> None` | Every 20 ms: try the queued messages again; drop and count a message that still fails after 1 s (§7.1, SPK-01) |
| `publish_sighting` | `(robot: str, marker_id: int, position: Tuple[float, float, float], distance: float, stamp: Time) -> None` | Publish `FoundMarker` with plain Python types |
| `on_log_timer` | `() -> None` | Log the number of failed lookups every 10 s |

### `nodes/leader.py` (C) — one class, one global instance

**`class Leader(rclpy.node.Node)`** — an adapter around `Mission`. It holds the
ROS clients, the `MarkerRegistry` and the allocator, and turns ROS callbacks
into mission events.

| Member | Signature | Purpose |
|---|---|---|
| `__init__` | `()` | Parameters (logged at start); subscriptions `/map`, `/found_marker`, `/<robot>/odom`; one `NavigateTo` action client per robot; client for `/set_marker_position`; mission timer (`tick_rate`) and steady-clock log timer; creates `MarkerRegistry`, `GreedyAllocator` and `Mission(allocator, self.path_cost, self.meeting_points, params)` |
| `on_map` | `(msg: OccupancyGrid) -> None` | Static grid, planning grid and wall distance |
| `on_odom` | `(robot: str, msg: Odometry) -> None` | Store the robot position |
| `on_found_marker` | `(msg: FoundMarker) -> None` | `registry.add(Sighting(...))` |
| `on_timer` | `() -> None` | Before `Started`: compute the viewpoints once the map and all odometry are there, check the start conditions, and send `Started` when they have held for 2 s. After that: `Tick`. Always: `report_markers` |
| `on_log_timer` | `() -> None` | Until `Started`, every 5 s: log the unmet start conditions, and log an error if a robot's `aruco_markers` or `camera/image_raw` has no publisher |
| `compute_viewpoints` | `() -> List[List[Point]]` | Start field from both robots' snapped cells, then `generate_viewpoints` for pass 0 and pass 1 |
| `dispatch` | `(event) -> None` | `self.execute(self.mission.handle(event))`; log state changes |
| `execute` | `(commands: List[Command]) -> None` | Run each command as a ROS call |
| `send_goal` | `(robot: str, goal_id: int, target: Point, spin: bool) -> None` | `send_goal_async` with a done callback |
| `on_goal_response` | `(robot: str, goal_id: int, future) -> None` | Store the goal handle for that `goal_id`; a rejected goal → `dispatch(GoalFinished(..., success=False))` |
| `on_goal_result` | `(robot: str, goal_id: int, future) -> None` | `dispatch(GoalFinished(...))` |
| `cancel_goal` | `(robot: str) -> None` | `cancel_goal_async` on the handle of the robot's current goal |
| `report_markers` | `(now: float) -> None` | Once the service is available: `call_async` for every `Report` in `registry.reports_due(now)`, with `z = 0` |
| `on_report_response` | `(report: Report, future) -> None` | `registry.on_result(...)`; a newly accepted marker → `dispatch(MarkerAccepted(...))` |
| `robot_field` | `(robot: str) -> np.ndarray` | Cost field with the robot's cell, snapped to the nearest free cell, as source; cached while the robot stays in that cell |
| `path_cost` | `(robot: str, target: Point) -> Optional[float]` | `CostFn`: `cost_at(robot_field(robot), grid, target)` |
| `meeting_points` | `(exclude: Sequence[Point]) -> Optional[Dict[str, Point]]` | `core.meeting.meeting_points` with `registry.accepted_position(4)` and both robots' fields |

`main()`: create the node and spin it in the default single-threaded executor.
All service and action calls use `call_async` / `send_goal_async` with
`add_done_callback`. No `spin_until_future_complete` inside callbacks.

## Tests (`rescue_team/test/`)

Unit tests cover the logic that is easy to get wrong. They run with `pytest`
without ROS, also in the Foxy VM.

| File | Covers |
|---|---|
| `test_geometry.py` | `wrap_angle`, `yaw_from_quaternion`, `rotate`, `transform_point` against hand-computed cases |
| `test_grid.py` | `world_to_cell` / `cell_to_world` round trip, row flip in `from_yaml` (a known wall lands at its metric position), unknown cells occupied, `downsample`, `inflate`, `is_known_wall` |
| `test_distance_transform.py` | Field values on a small known grid, wall in the way, no corner cutting, unreachable cell is `inf`, several sources, wall distance, descent reaches the source, `avoid` disc forces a detour, planner on w1 with start and goal inside inflated walls |
| `test_path.py` | Simplified path never crosses a blocked cell and keeps only corners, `remaining_length`, `ProgressMonitor` |
| `test_traffic.py` | Head-on in a corridor, driving away from a close robot, other robot moving away, other robot standing on the path, right of way |
| `test_marker_registry.py` | Median ignores an outlier, closer half after a rejection, waiting for new sightings after a second rejection, resend after the timeout, late `true` after a resend, accepted marker never reported again |
| `test_viewpoints.py` | Points free and with spin clearance, reachable, close to a wall, no duplicates, pass 1 offset |
| `test_allocation.py` | Cheapest free viewpoint, unreachable skipped, reservations split two robots, failure handling, `release`, `free_count` |
| `test_meeting.py` | Alcove where only one robot fits (point B at the opening), separation, exclusion, no pair → `None` |
| `test_mission.py` | Every row of the transition table with a fake allocator, cost and meeting function; deadlines; stale `goal_id`; meeting retries; `Finish` |
| `data/` | Copies of the course map files of w1–w5 (`.png` and `.yaml`) |

Tests for `lidar` and `controller` are added where they help during
development. Of the linter tests created by `ros2 pkg create`, `test_flake8.py`
and `test_pep257.py` are kept; `test_copyright.py` is removed because the files
carry no licence header. The two linter tests import the ROS 2 lint packages, so
outside the VM `pytest` is run with both files ignored (see README, Testing).
